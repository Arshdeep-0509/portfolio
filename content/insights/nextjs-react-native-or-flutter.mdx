"Should we build a website or an app?" is one of the first questions founders ask, and it's usually
asked too early. The right answer depends far less on technology than on who your users are, how
they'll find you, how often they'll come back, and what you can afford to maintain once the first
version ships.

Here's the short version. If people will discover you through search or links, use you on a laptop
at work, or only need you occasionally, start with a web app — Next.js is my usual choice. It's one
codebase, it updates instantly, and every page can be found on Google. If your product lives in
people's pockets — daily habits, notifications, the camera, location, offline use — a mobile app
starts to earn its extra cost. Then the question becomes React Native or Flutter.

Both are mature, both build for Android and iOS from one codebase, and both can produce apps that
feel native. React Native shares a language and a lot of thinking with a React or Next.js web app,
which matters if you'll have both. Flutter gives you very consistent rendering across devices and is
popular with teams who don't already work in JavaScript. For most MVPs, either will do the job; the
deciding factors are your team, your web plans and the specific features you need.

There's also a fourth option founders overlook: start with a fast, mobile-first web app, prove the
idea, and add a native app once you know people want to come back daily. On budget phones and patchy
networks, a well-built web app can feel quicker than an app users first have to download.

In this post I compare the options on the things that actually matter for a first product, and give
you a simple decision path you can use in an afternoon.

## A simple decision path

```txt
Will users find you through search or shared links?
  └─ yes → start with a web app (Next.js)
  └─ no  → Is daily use, push, camera or offline essential?
            └─ yes → mobile app (React Native or Flutter)
            └─ no  → mobile-first web app, add an app later
```
